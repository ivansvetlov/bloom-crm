# UX доставки продуктов (Everest) → гибрид для курьерского приложения флористики / Flowwow

**Источники (2021–2022, Everest Research):**  
- [Часть 1 — сравнительный анализ интерфейсов](https://research.everest.cx/ux-prilozhenij-po-dostavke-produktov-chast-1)  
- [Часть 2 — UX процесса покупки](https://research.everest.cx/ux-prilozhenij-po-dostavke-produktov-chast-2)  

**Объекты ресерча:** Лента, ВкусВилл, Азбука вкуса, Пятёрочка, Перекрёсток.  
**Дата отчёта:** 2026-08-01  
**Контекст:** потенциальное курьерское / delivery-приложение под сеть флористики и контур Flowwow + Bloom CRM.

> Важно: снимки приложений — сентябрь 2021. Паттерны и антипаттерны актуальны; конкретные экраны могли измениться.

---

## 1. Что взяли из части 1 (каркас продукта)

### 1.1 Старт пути
| Паттерн | Сильные | Антипаттерн |
|---------|---------|-------------|
| Одно приложение = одна задача | Пятёрочка (сразу каталог/доставка) | Несколько app с похожим описанием (Перекрёсток / X5) — путаница до первого запуска |
| Онбординг с ценностью + скип | Азбука (обучение + гео), промокод в ВкусВилл/Перекрёсток | Длинный онбординг без «зачем мне это» |
| Разрешения с объяснением | Лента (кастомные алерты «зачем гео/пуши») | Системный алерт без контекста |
| Адрес **до** корзины | Все так или иначе | Молчаливое «ассортимент другой» после смены адреса |

**Для флористики:** один app «курьер / доставка букетов», не путать с B2B-кабинетом салона. Гео/слот — до «взять заказ в работу».

### 1.2 Главный экран и адрес
- Адрес сверху: от него зависят **зона, ETA, цена доставки, иногда ассортимент**.  
- Зону на карте показывать (Лента/Пятёрочка/Перекрёсток), а не «точка не ставится» (Азбука).  
- Вне зоны — альтернатива или сбор «откройте доставку сюда» (ВкусВилл).  
- Стоимость доставки — **рано**, не только на чекауте.

### 1.3 Авторизация
- Откладывать до оформления / назначения курьеру.  
- Телефон как ключ, минимум полей.  
- Не требовать логин для просмотра смен/карты слотов (если политика позволяет).

## 2. Что взяли из части 2 (корзина → доставка)

### 2.1 Поиск и каталог (для курьера = поиск заказов / адресов)
| Сильное | Перенос на курьера |
|---------|-------------------|
| Поиск с 3 символов + история + популярное | Поиск заказа по адресу / телефону / #FW |
| Фильтры под сценарий (жирность, фасовка) | Фильтры: «горящие», «мои», «район», «нужен термопакет / хрупкое» |
| Мини-карточка: фото, имя, цена; вес отдельно | Мини-карточка: фото букета, адрес, ETA, сумма, канал (FW/прямой) |
| Out of stock: «завтра / привозите больше» | «Уже забрали другой курьер» / «салон ещё собирает» с ясным CTA |

### 2.2 Корзина и оплата (для клиента; курьер видит зеркало)
- Мини-корзина с **суммой** (не только count).  
- До бесплатной доставки — прогресс (Лента/Азбука).  
- Слоты: ASAP **и** окно времени (Перекрёсток-модель).  
- Прозрачность предоплаты на «весовых» / досборке: показывать **что спишут**.  
- Наличные: «нужна сдача с N» (ВкусВилл) — для курьера флористики реже, но для прямых оплат при вручении — да.

### 2.3 Статусы и трекинг
- **Прогресс-бар статусов** (ВкусВилл/Пятёрочка/Перекрёсток) лучше одного «текущего» статуса.  
- Окно отмены/правки первые минуты.  
- После оформления — «что дальше» (короткая инструкция).  
- Фидбек: NPS/звёзды + простые эмоции, без 9 полей формы (антипаттерн Азбуки).

### 2.4 Фишки
- Списки / пакетный поиск (Лента) → у курьера: «маршрут из N адресов».  
- Персонализация (ВкусВилл) → у курьера: любимые районы, приоритет «хрупкое/фото».  
- Поддержка: чат + FAQ + звонок в один тап (не копировать номер).

## 3. Гибрид: сильнейшее решение «Bloom Courier» (для сети + Flowwow)

Целевые роли: **курьер** (mobile-first), **салон/менеджер** (назначение, фото, статусы в Bloom), **клиент** (статусы уже частично на Flowwow/в мессенджере).

### 3.1 Принципы (гибрид)
1. **Одна задача на экран** — взять, ехать, сфотографировать, сдать.  
2. **Адрес и ETA до принятия** заказа в работу.  
3. **Прозрачные статусы** как на витрине: Собран → Фото → В пути → Доставлен.  
4. **Фото до выезда** (Flowwow-паттерн) = must, не опция.  
5. **Двухсторонний sync** с Bloom (и при возможности с Flowwow): статус курьера = статус заказа.  
6. **Право на ошибку:** отмена/переназначение в первые N минут.  
7. **Не заставлять думать:** кнопки-глаголы («Забрал», «Фото отправлено», «Еду», «Вручил»).

### 3.2 Информационная архитектура (курьер)

```
Таббар
├── Сейчас      — активный заказ / навигация / ETA
├── Смена       — очередь: горящие → ближайшие → остальные
├── Маршрут     — карта/список точек (без «украшательства»)
└── Профиль     — смена, контакты салона, FAQ, поддержка
```

**Смена (inbox заказов)** — как каталог в grocery:
- Фильтры: ASAP | окно 18–20 | только FW | только прямые | хрупкое  
- Мини-карточка: фото букета · адрес · ETA · ₽ · бейдж канала  
- Пустой стейт: не пустой экран, а «тихие часы / ожидайте» + подсказка

**Карточка заказа (аналог PDP):**
- Фото (gallery thumbs)  
- Состав (коротко)  
- Адрес + подъезд/домофон + комментарий  
- Слот: «как можно скорее / от 30 мин / 18:00–19:00» — **единый стиль чипов**  
- Кнопки по этапу (только релевантные)  
- Связь: позвонить клиенту / в салон (tap-to-call)

**Трекинг (shared с клиентом):**
- Progress: Принят салоном → Собран → Фото → У курьера → В пути → Вручён  
- Клиенту: push + deep-link (как в grocery), без отдельного «тяжёлого» app если уже есть мессенджер/Flowwow

### 3.3 Матрица «взяли у кого»

| Фича | Источник | В Bloom Courier |
|------|----------|-----------------|
| ASAP + слот | Перекрёсток | Слоты доставки букетов |
| Зона на карте + вне зоны | Лента / ВВ | При назначении курьеру |
| Прогресс статусов | ВВ / Пятёрочка | Основной трек |
| Фото «до» | Flowwow (наш домен) | Обязательный шаг |
| Объяснение permissions | Лента | Пуши гео «чтобы строить маршрут» |
| Мини-карточка + сумма | grocery | Inbox смены |
| Замена / «разобрали» | Азбука / Пятёрочка | «Букет пересобран — новое фото» |
| Фидбек после | NPS-лайт | Оценка курьера + «букет как на фото?» |
| Поддержка | чат + call | В профиле + на экране заказа |

### 3.4 Отличия флористики от grocery (критично)
| Grocery | Цветы / Flowwow |
|---------|-----------------|
| Много SKU, весовой товар | Мало позиций, **визуал = продукт** |
| Замена «похожим молоком» | Замена только с **новым фото** и согласием |
| ETA 30–90 мин слоты | ETA жёстче к событию (18:00 «к празднику») |
| Курьер = «коробки» | Курьер = **хрупкое + презентация** |
| Чек весовой после сборки | Цена чаще фикс; доплата — редкость |

### 3.5 MVP scope (что запускать первым)
**P0**
1. Inbox смены + фильтр ASAP  
2. Карточка заказа + навигация (deep-link в карты)  
3. Статусы + фото до выезда  
4. Sync в Bloom (и отображение клиенту)  
5. Tap-to-call  

**P1**  
Мульти-stop маршрут, чат с салоном, offline-очередь статусов, бонусы/чаевые.

**P2**  
Оптимизация маршрута, heat-map пиков (8 Марта), рейтинг курьера как у «супермагазина».

### 3.6 Метрики успеха
- Time-to-accept (заказ → курьер взял)  
- % заказов с фото до выезда  
- On-time % к слоту  
- CSAT «соответствие фото»  
- % отмен после «в пути» (должно → 0)

### 3.7 Риски
- Двойной sync Bloom ↔ Flowwow (конфликт статусов) — **один source of truth: Bloom**, Flowwow как consumer.  
- Давление пиков — отдельный «режим 8 Марта» (упрощённый UI, только P0-кнопки).  
- Серые мессенджеры у менеджеров ≠ канал курьера (курьер app — официальный контур).

## 4. Вывод

Everest-ресерч даёт не «дизайн кнопок», а **правила разговора с пользователем**: адрес и ограничения рано; статусы прозрачны; фото/замены честны; корзина и ETA не врут; поддержка в один тап.

**Гибрид для флористики:** grocery-дисциплина статусов и слотов + Flowwow-культура **фото до доставки** + Bloom как операционный hub. Это и есть основа курьерского приложения «под Flowwow-сеть», без копирования grocery UI один в один.
