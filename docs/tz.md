# Техническое задание — Bloom CRM

| | |
|---|---|
| **Продукт** | Bloom CRM — операционный кабинет для цветочного бизнеса |
| **Домен** | crmbloom.ru |
| **Дата** | 2026-08-01 |
| **Статус** | Требования к системе (15 блоков), рабочая редакция |

**Идея в одной фразе:** один кабинет, где заказы с маркетплейса, прямые продажи и переписки (WhatsApp / Telegram / MAX) живут вместе — без Excel и «где этот букет?».

---

## 1. Единый кабинет

- Один веб-кабинет в браузере (компьютер, планшет, телефон).
- Вход по логину и паролю, без СМС.
- Несколько сотрудников работают одновременно; число пользователей не ограничено.
- Менеджеры видят все магазины и все заказы.

## 2. Заказы с маркетплейса в одном месте

- Оплаченный заказ с подключённого маркетплейса появляется в кабинете за несколько секунд: звук + метка «Новый».
- Фоновая сверка с маркетплейсом, чтобы ни один заказ не потерялся.

## 3. Карточка и список заказов

**В карточке:** состав с фото и суммой; дата и время доставки; способ доставки; адрес; покупатель и получатель (имя, телефон); комментарии; текст открытки; фото букета до/после.

**В списке (все точки):** срочные сверху; фильтры по магазину, филиалу, статусу, дате; поиск по номеру, имени, телефону.

**История:** кто и когда что сделал; внутренние заметки; напоминания (поздравление, дата, пометки).

## 4. Управление статусами из кабинета

Цепочка: **Принять → Собран → Передан в доставку** (или «Готов к самовывозу») → **Выполнен**.

- Смена статуса в Bloom синхронизируется с маркетплейсом и обратно.
- Отказ от заказа с причиной; загрузка фото букета.
- Отмена покупателем на стороне маркетплейса — видно в кабинете + уведомление.

## 5. Уведомления

- Новые заказы — в Telegram или VK.
- Если заказ не приняли за **3 минуты** — повторное напоминание.

## 6. Прямые продажи

Заказы мимо маркетплейса (постоянные клиенты, телефон, мессенджеры) менеджер создаёт вручную:

- состав, сумма, получатель, адрес, дата;
- магазин-исполнитель, источник, способ оплаты.

В общем списке наравне с заказами маркетплейса, метка **«Прямой»**, те же статусы и напоминания. **На маркетплейс не передаются.**

## 7. Чаты: WhatsApp, Telegram, MAX

- Личные (не бот-) аккаунты: для клиентов ничего не меняется.
- Раздел **«Чаты»**: все диалоги в одном окне; ответ текстом, фото, файлами.
- Из переписки — создание заказа в один клик.
- История: насколько отдаёт каждый мессенджер; новая переписка хранится полностью.
- Уведомления о новых сообщениях — как по заказам.
- Безлимитные / недорогие варианты подключений — по согласованной платформе.

## 8. Аналитика

- Выручка и число заказов за период, средний чек, динамика.
- Фильтры по магазинам и филиалам; топ товаров и категорий.
- Раздельно: маркетплейс и прямые продажи.
- По клиенту: сумма, средний чек, периодичность покупок.

## 9. Надёжность подключений

Мониторинг интеграций. Если отвалился ключ маркетплейса или аккаунт мессенджера — сразу сообщение в Telegram: что случилось и что сделать.

## 10. Витрина и точки

Управление витриной всех точек из кабинета:

- цены и скидки;
- остатки;
- скрытие / показ товаров;
- массово по магазинам и филиалам.

По возможности (уточняется с API маркетплейса): топ магазинов, рейтинги, отзывы.

## 11. Гарантия и поддержка

Бизнес переносится в одну систему — нужна уверенность в надёжности, безопасности, отсутствии «лагов» и наличии поддержки (в идеале **гарантия от года**), сравнимо с зрелыми CRM на рынке. Отдельно согласуются: SLA, резервное копирование, эскалация инцидентов.

## 12. Месячная стоимость

Прозрачный **итоговый opex** в месяц: серверы, домены, мессенджеры / соцсети и прочие обязательные сервисы.

## 13. Лояльность

Отдельное ТЗ (вне текущего объёма, пока не расписано).

## 14. Онлайн-оплата

Привязка банка / эквайринга — отдельным этапом после согласования схемы.

## 15. Развитие

- Редактирование карточки клиента.
- Доработки CRM по необходимости (бэклог после запуска).
